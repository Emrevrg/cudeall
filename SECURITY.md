# Security policy

## Reporting a vulnerability

Please do not disclose credentials, browser session data, or an exploitable vulnerability in a public issue.
Use GitHub's **Report a vulnerability** flow in the repository's Security tab when private vulnerability reporting is enabled. Include the affected version, the smallest reproducible case, and impact. Do not attach real secrets; use placeholders.

If private reporting is unavailable, open a minimal issue asking for a private contact channel without publishing exploit details.

## Scope

CudeAll can read project files, access public web URLs, control a configured browser or desktop, and write local task, memory, and automation data. Report unexpected access beyond the documented workspace or permission boundary, secret disclosure, unsafe URL handling, or an unintended external action.
